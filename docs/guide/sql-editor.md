# SQL editor

- **Editor action rail**: compact icon buttons run vertically beside the line numbers. Hover for action names, explanations and current Timeout/Autocommit settings. The rail scrolls independently when the editor is short; Execute changes to Cancel during execution. The connection name remains above the editor. Desktop layout and tooltip acceptance are pending.

- **Dialect syntax highlighting**: Keywords across PostgreSQL, MySQL, SQLite, and ANSI SQL dialects are highlighted. Parameter placeholders (`:name`, `@name`, `$1`, `?`) are distinctly colored. The editor does not validate the whole script while typing. SQL syntax errors are reported from the database when SQL is executed.
- **Snippets & Templates**: Toolbar **Snippets…** dialog provides searchable standard templates categorized into Queries, DML, DDL, and Advanced (CTEs, Joins, Window Functions). Selecting a template shows a live preview; pressing Enter or clicking Insert places the template at the caret or replaces selected text with complete Undo support (`Cmd/Ctrl + Z`).
- **Parameter binding and variable prompts**: When executing a statement containing named (`:param`, `@param`) or positional (`$1`, `?`) parameters, a **Bind Query Parameters** modal prompts for typed values (`String`, `Integer`, `Float`, `Boolean`, `Date/Time`, `NULL`, `Raw SQL`). Parameter values are validated, escaped against SQL injection, previewed in real time, and remembered across successive executions in the tab session. MySQL/MariaDB reserve `@name` and `@@name` for native server variables: Execute and modal preview preserve them, including names containing `$`, `.`, or quoted text. Use `:name` or `?` for client prompts on those providers.
- **External SQL files**: Import SQL copy… reads one UTF-8 `.sql` file (up to 16 MiB) into a new numbered script on the current script's connection. The imported script uses normal autosave; the source file stays independent. Save SQL copy… writes the captured editor snapshot to another `.sql` destination using atomic replacement, with errors/cancel feedback. Neither action executes SQL. Native file-dialog acceptance is pending.
- **Find / Replace**: toolbar dialog for literal, case-sensitive search across the active script. Find next wraps and selects the match; Replace changes an exact selected match then finds the next; Replace all changes non-overlapping matches in one Undo step. Empty replacement removes text; an empty search never inserts text. Tab switches fields, Enter finds next, and Escape clears field selection before closing. Changes use normal autosave. Manual dialog acceptance is pending.
- **Line editing**: Comment / Uncomment, Indent and Outdent toolbar actions change the current line or selected lines as one undoable edit, using normal autosave. Selection ending at the next line's start excludes that line. Comment toggles `-- ` after indentation, preserving blank lines. Indent adds four spaces; Outdent removes one leading tab or up to four spaces. Unicode and line endings are preserved; selected lines stay selected. Manual toolbar acceptance is pending.
- **Shared text editing**: SQL, connection fields (including passwords), filter/fetch size, script search/rename and inline cell editors share command, clipboard and mouse selection handling. Esc clears the selection without moving the caret or changing text (press Esc again to dismiss a dialog or cancel a cell edit); Shift-click extends or shrinks from the original anchor; double-click selects a line (the full value in a one-line field). Copy/cut use the selected text and do nothing without a selection. Paste replaces the selection; one-line fields flatten pasted line breaks and numeric fields keep only digits.
- **PostgreSQL query plans**: Explain/Analyze use distinct icon buttons with hover explanations in the editor action rail. **Explain** plans the statement under the caret; **Analyze (executes SQL)** runs it with `EXPLAIN (ANALYZE, BUFFERS, FORMAT JSON)`. The collapsible tree shows operators, costs, row estimates, actual per-loop timings/rows and buffer usage. Switch to raw JSON for the full output; each result tab preserves its plan view. Explain and Analyze use the SQL tab's persistent session, including temporary tables, session settings and uncommitted changes. Analyze writes participate in the tab's open transaction; SQL errors retain the session for Rollback or ROLLBACK TO, while Cancel rolls back and closes it. Analyze executes the original statement, including writes and function side effects; Cancel uses the existing query cancellation. SQLite also offers **Explain** using native `EXPLAIN QUERY PLAN` on the SQL tab session. Its tree shows scan, search and other operators, with the raw native rows available in the result grid. SQLite provides neither estimated costs nor runtime metrics in this view. The action accepts one query or DML statement. PRAGMAs are excluded because SQLite can apply them during statement preparation.
- Scripts are `.sql` files saved per connection under `<config dir>/scripts/<connection id>/Script-<n>.sql` (on macOS `~/Library/Application Support/com.fastdb.FastDB/scripts`), saved atomically in the background after a short pause in typing. Run, tab close and Quit wait for pending saves; the global Quit menu/shortcut defers workspace access until GPUI finishes event dispatch; a save failure keeps the tab open and shows an error.
- `Cmd + ]`, the **+ SQL** button or **SQL Editor** in a connection's right-click menu reopens the connection's latest script, or creates `Script-1` when it has none. When the latest script is already open, a **Choose SQL script** dialog lists the connection's scripts by time with a search box, a **New script** button and **Show scripts for all connections**.
- Table and script tabs keep their connection identity, results and staged edits when switching connections. Editing a connection preset does not change an open session's SQL dialect.
- A script tab runs on its own connection: selecting it switches the active connection. The workspace has a draggable title bar showing the connection and active document and a horizontal actions/context toolbar. Below them, Connections owns the left panel header and document tabs belong to the right content panel. Connection context is shown once on the workspace toolbar. Create connections from the toolbar; open SQL tabs from the toolbar or the connection context menu. The tab-row **+ SQL** button is removed; document tabs are inside the right content panel, beside the separately resizable Connections panel.
- **Editor action rail**: Execute/Cancel and PostgreSQL Explain remain beside the SQL gutter.
- **Transaction toolbar and Transaction log**: Commit, Rollback and an Auto/Manual selector with SVG icons are always visible on the horizontal workspace toolbar, including when no tab is open. Commit/Rollback are disabled in Auto-Commit mode; in Manual mode they are enabled for connected SQL and table tabs whose driver supports transactions. The selector splits into independent hit targets: the `T` icon and `▾` arrow open the mode/isolation menu (enabled for transaction-capable tabs when idle), while clicking the **Auto** / **Manual** label opens the **Transaction log** modal at any time. The mode menu opens at the measured bottom-left of the selector and stays within the window; its position does not depend on where inside the button you click. Scrolling the toolbar, resizing the window or changing tabs dismisses the popup. The menu contains Auto-Commit, Manual Commit and supported isolation levels. The active known isolation level appears in the Manual Commit label. **Transaction log** records every executed SQL statement in the current app process (script statements, table reads/writes, transaction controls, query plans, CSV transfers and metadata queries), including failures and cancellations, while omitting unexecuted queued statements, bound parameter values, credentials and result values. Records live in a private temporary file that is deleted on normal exit and cleaned up on later startups if a crash occurred; the modal pages and searches (`Time (UTC)`, `Type`, `Text`, `Duration`, `Rows`, `Result`) from disk with bounded memory and drops loaded records when closed. Database and schema selectors follow the transaction group. Smart commit is not implemented.
- Table names completed after `FROM` / `JOIN` get an alias (`"featureFlag" f`), and `f.` completes that table's columns.
- **Editor viewport**: long SQL lines and multi-line scripts scroll horizontally/vertically inside the editor pane, with visible scrollbar tracks. Moving the caret reveals it on both axes; select-all keeps the viewport steady.
- **Selection and clipboard**: double-click SQL text to select the entire line (including its line break); dragging after a double-click extends by whole lines. `Cmd/Ctrl + A` highlights the entire script clearly; drag to select text; hold Shift and click to extend or shrink the selection from its original anchor (including after a double-click), or use Shift + navigation keys; `Cmd/Ctrl + A/C/X/V` selects all, copies, cuts or pastes. Typing replaces the selection; undo/redo restores edits.
- `Cmd/Ctrl + Enter` runs exactly the selected SQL when text is highlighted. Otherwise it runs the statement containing the caret, bounded by an unquoted semicolon or the next independent top-level query (including consecutive SELECT queries without semicolons). Nested queries, CTEs, INSERT … SELECT and UNION chains remain together. Its rows stream into the grid below the editor.
- **Run script** (`Cmd/Ctrl + Shift + Enter`) executes semicolon-delimited statements sequentially, exactly once, stopping on the first error or Cancel. Each statement streams its full result into the paged/spilling store, retaining the latest 20 results.
  - **PostgreSQL** keeps one dedicated physical session per SQL tab across Execute and Run script, separate from browsing/metadata and row-edit Save. Temporary tables and session settings survive successive runs. **Begin / Commit / Rollback** toolbar actions and SQL transaction controls can span runs; SAVEPOINT, ROLLBACK TO [SAVEPOINT] name and RELEASE [SAVEPOINT] name support partial rollback. The footer reports transaction state after acknowledged controls. BEGIN options, chaining and prepared transactions remain unsupported. Autocommit defaults On; selecting Off enables the client-managed behavior described below.
  - PostgreSQL SQL errors stop remaining statements and retain the tab session, allowing ROLLBACK TO or Rollback to recover a failed transaction. Cancel rolls back and closes the session with bounded cleanup. Closing a tab or disconnecting closes its socket and PostgreSQL rolls back uncommitted work. Earlier committed/autocommit writes remain applied. Session loss is terminal with no automatic reconnect, replay or COMMIT retry; disconnect/reconnect opens a fresh session on the next execution. A lost COMMIT acknowledgement can mean an uncertain commit outcome.
  - **SQLite** also uses a dedicated connection per SQL tab, with Begin/Commit/Rollback and SQL savepoints across executions. Main database contents are shared with browsing; TEMP objects are private to the tab. Each in-memory connection preset has its own database, shared only by its own tabs. Cancel, tab close and disconnect close the tab connection and roll back uncommitted writes. The footer reads SQLite's native autocommit state after each statement, including errors and standalone SAVEPOINT/RELEASE. SQLite BEGIN options and trigger bodies use native SQLite semantics. Desktop acceptance is pending.
  - **MySQL/MariaDB** SQL tabs now own dedicated physical connections, retaining temporary tables, user variables and transactions across runs. Begin/Commit/Rollback and SQL savepoints use that same connection; the footer reads native transaction flags, including implicit DDL commits. SQL errors stop the script and keep a recoverable session; lost connections are discarded without reconnecting or replaying the failed run. Cancel closes the session, using a separate bounded connection to terminate an active server query. Normal tab closure rolls back before disconnecting; cleanup failures are reported. DDL and earlier committed/autocommit writes remain applied. MySQL live integration tests cover these paths; separate MariaDB and desktop acceptance remain pending.
  - **SQL Server, Oracle and Db2** open a dedicated ODBC session per SQL tab. SQL Server uses native T-SQL transaction controls and reads server transaction state after each batch. Oracle and Db2 use the ODBC transaction API for toolbar Begin, Commit and Rollback. Use native savepoint syntax for each provider. Cancel requests SQLCancel and discards the session. The vendor may take time to finish cancellation. Live acceptance for these new paths is pending.
  - **Vendor batch syntax** is available through Run script. MySQL/MariaDB supports `DELIMITER`, SQL Server supports a standalone `GO`, Oracle uses a standalone `/` after PL/SQL blocks, and Db2 supports `--#SET TERMINATOR` for compound statements. SQLite trigger bodies and PostgreSQL dollar-quoted bodies can contain semicolons. Use Run script for compound SQL so the full script determines its boundaries. Explicit whole-block selection also works for Oracle PL/SQL. GO repetition counts, MySQL executable comments and mode-dependent backslash quoting are rejected.
- **Result tabs** retain the latest 20 statement results per script, including each result's SQL, grid, selection, fetch state and errors. Switch or close results with the × button on each result tab after execution completes. Closing the selected result selects its neighbor; closing the last result clears the grid. Save or Cancel pending edits before closing the selected result. Older results are released automatically.
- **Find in result…** below the editor searches the current loaded result with literal, case-sensitive Next/Previous and wrap. It includes displayed staged values, preserves edits and does not execute SQL or fetch more rows. Searches run in the background with Cancel; Close cancels pending work; Escape first clears input selection, then closes. Stale results are discarded. SQL NULL/unset values are skipped and the query limit is 4,096 UTF-8 bytes. Opening Find keeps automatic fetch paused through dialog closure; later manual vertical scrolling or a new result restores it. See the [table grid guide](navigator-and-tables.md) for scope; desktop acceptance remains pending.
- **Database…** lists databases for PostgreSQL, MySQL/MariaDB and SQL Server. Selecting one creates an empty temporary SQL tab with its own driver and session. The original transaction and temporary objects remain in the original tab. Use **Save SQL copy…** to keep text from a temporary tab. A connection replacement or disconnect closes its session.
- **Schema…** changes the search path or current schema on an idle PostgreSQL, Oracle or Db2 tab and displays native read-back. MySQL/MariaDB treats schemas as databases, so use **Database…**. SQLite and SQL Server do not offer a mutable session default schema. The selector supports up to 64 entries. For larger catalogs, use explicit session SQL or a separate saved connection.
- **Isolation…** opens a SQL preview and native choice dialog for an idle SQL tab. PostgreSQL offers Read committed, Repeatable read and Serializable; MySQL/MariaDB also offer Read uncommitted; SQLite offers Serializable only. SQL Server and Db2 offer their four standard levels. Oracle offers Read committed and Serializable with server acknowledgement. Apply runs on that tab's pinned session, then reads back its native setting into a result grid where supported. Each setting/read-back statement has a 15-second deadline independent of the ordinary SQL timeout preset. Commit or Rollback first when a transaction is active or its state is unknown. Closing the dialog cancels; a disconnected/replaced connection invalidates the pending choice. Settings apply to future transactions and are not restored after session closure. Desktop dialog acceptance and separate MariaDB runtime validation remain pending.
- **Autocommit… (PostgreSQL/SQLite/Oracle/Db2)** changes the open SQL tab's client mode without executing SQL immediately. Off inserts BEGIN before ordinary SQL when idle; subsequent runs share the transaction until Commit/Rollback. Off stays selected after either boundary or session closure. Explicit transaction controls remain in order, and Explain/Analyze uses the same transaction. On is blocked during active, failed or unknown transactions until explicit recovery. Mode is not persisted after tab closure, and disconnected work is never replayed. Desktop acceptance remains pending.
- **Autocommit… (SQL Server)** toggles native implicit transactions and shows read-back. Commit or Rollback before switching On with active or unknown state.
- **Autocommit… (MySQL/MariaDB)** previews native Off/On settings and reads back `@@SESSION.autocommit` on the same SQL-tab session. **On is blocked while a transaction is active or its state is unknown**; Commit or Rollback first. Off can preserve an existing transaction and makes subsequent transactional work wait for Commit/Rollback. This control never commits pending work to enable On. Settings use the same 15-second deadline and stable tab/connection guards as Isolation. A closed session returns to server defaults on its next connection. Desktop/MariaDB runtime acceptance remains pending.
- **Format** (`Cmd/Ctrl + Shift + F`) lays out the selection, or the whole script, as one undoable edit. Formatting preserves token/literal/comment bytes and adds line breaks at top-level clauses; it does not rewrite dialect-specific SQL.
- **History** lists up to 100 unique recent executions per connection, newest first; click an entry to insert it at the caret or replace selected text without executing it. History persists under `<config dir>/query-history` as plaintext SQL; queries larger than 64 KiB are omitted.
- **Rename** changes the current script's `.sql` filename without overwriting another file. **Delete** asks for confirmation and moves the file into its connection folder's `.trash`; restore it manually by moving the `.sql` file back. Both wait for queued autosaves; input is paused during the move.
- Plain `SELECT` / `WITH` statements without their own `LIMIT` are fetched in chunks of the fetch size, like table data; other statements run as written.
- Schema-aware completion of keywords, functions, tables and `table.` columns, accepted with `Tab` or `Enter`.
- The error of a failed statement is shown above the result, in script and table tabs.

- **Execution log** toggles a per-tab panel retaining the latest 100 statement outcomes across runs, independent of the latest 20 result grids. Each entry includes a SQL preview (240 characters), elapsed milliseconds, returned rows or native affected-row count, notices and errors. The log exists only while the tab is open; it is not saved across restarts. Messages/errors are capped at 1,024 characters and 21 messages per entry; PostgreSQL forwards up to 20 notices plus a truncation indicator per statement. Earlier outcomes survive subsequent errors and result eviction. PostgreSQL error positions are one-based character offsets within the executed statement (internal-query positions are labelled separately); other providers show positions only when included in native error text.
- **Load editable result (PostgreSQL)** reads a direct `SELECT * FROM schema.table` on a separate connection. FastDB verifies native table/column identities and the complete primary key. Supported permanent ordinary tables allow updates to non-key Boolean, integer, text, varchar and UUID columns. Views, joins, expressions, extra clauses, inherited or partitioned tables, row security, user triggers and rules stay read-only. Save binds values, checks original values and revalidates the source under a table lock, then reloads stored values. A conflict rolls back the whole Save and retains staged edits for inspection or Cancel. Save commits through an isolated connection, separately from any transaction open in the SQL tab. Query-result row insertion and deletion remain unavailable.
- **Record** combines with either Grid or Text for the selected loaded row: Grid shows a two-column Name / Row #n table; Text shows the same fields in an aligned monospace table. Switching Grid/Text preserves the row and Record toggle. Previous/Next navigate loaded rows; Copy record copies the current field page. Toggle Record off, choose All rows, or press Escape to return to all rows without changing Grid/Text. See [table/result controls](navigator-and-tables.md) for bounds, refresh and read-only behavior.
- **Timeout** cycles through off (default), 5s, 30s, 60s and 300s for the current SQL tab. It applies separately to each executed statement, including Explain/Analyze and transaction buttons. Timeout is a best-effort cancellation request, not a hard server deadline or a guarantee of rollback. On expiry, execution stops before the next statement, cancellation is requested once and cleanup retains the busy state until the provider stops. PostgreSQL timeout closes the pinned session and rolls back an open transaction; earlier committed/autocommit writes may remain applied. For ordinary providers, connection acquisition is included and a run-scoped cancellation flag prevents a queued statement from starting after expiry. If a vendor cannot promptly stop, the workspace remains busy rather than racing the next execution. Timeout changes apply to the next run and reset on tab closure.
- **Execution policy**: one SQL execution/script/row-save operation at a time across the workspace. Attempts to run another statement/script show a busy message; Execute becomes Cancel while an operation runs. No SQL is automatically queued or retried. Result selection becomes available after execution/cleanup finishes.
- **Provider feedback**: PostgreSQL reports command counts, server notices and native error positions; MySQL/MariaDB report native command counts and up to 20 server warning details (loaded on the same connection with a 5s bound). SQLite reports counts for non-result statements, including zero-row writes. ODBC reports native command counts where available; unknown counts are labelled unavailable. ODBC informational notices and structured error positions remain unsupported. Statements with result columns, including DML RETURNING, are shown as returned rows.

- **Result view labels**: Grid, Text and Record retain icons and vertical labels reading bottom to top on the left rail; Panels uses a grid-and-gear icon and reads top to bottom on the right rail. Glyph outlines preserve normal letter shapes without mirroring.

- **Result panel sizing**: before the first SQL execution, the editor fills the available space and the result area/footer stay hidden. Execution creates a visible result even for zero rows, commands or errors. Drag the horizontal divider up/down to resize results and editor; the editor share is bounded to 15–85% of the split area. Each tab keeps its own ratio while open. Closing the last result restores the full editor.
