# Navigator and table tabs

- **Plain-text results**: table data and SQL query results share the same non-wrapping monospace table component, with aligned headers, separators and padded values. Copy preserves the formatted text. The preview shows at most 2,000 loaded rows and 255 characters per column; NULL is shown as `[NULL]`.

## Database navigator

- **Multiple table selection**: click a relation to select it, then Shift+click another to select the inclusive range of visible relation rows. Repeated Shift+clicks keep the original anchor. Collapsed folders and filtered-out relations are excluded; if the anchor is hidden, the clicked row becomes the new anchor. Plain click resets to one selection. Press Escape to clear the selection and range anchor; open menus/dialogs and selected text handle Escape first. Double-click opens only the clicked relation; context-menu actions still apply to their clicked target. Selection is local to each connection.

Connections has its own left panel with its heading, search and tree. Document tabs belong to the SQL/table panel on the right. Drag the divider at the right edge of Connections to resize the two panels. Create connections and SQL scripts from the workspace toolbar.

- **Navigator search/filter**: one search field with a filter icon selects Connections, Catalogs and schemas, Tables/procedures/etc., or Files. The selected mode limits the results; hover the icon for its description. Search defaults to loaded relations in the connected active connection. An empty query preserves the connection tree in every mode; typing automatically shows matching results. Relation searches preserve the connection tree, expand the active connection and matching schema branches, and show matching relations inside their original folders with a Filtered by search label. Clearing the query restores the saved expansion state. Connection, schema, and relation filters use the active workspace metadata. Files searches saved SQL script names across connections and opens a selected script. Tables/procedures/etc. mode shows **Browse catalog objects…** when the query is empty; the catalog browser pages PostgreSQL sequences, routines, triggers and user-defined types with on-demand read-only metadata/source (256 KiB limit). Other providers show unsupported status. Favorites persist by connection, schema, kind, name and signature, with explicit missing-object and save-error feedback. Results are capped at 100.

- **Reveal active object** expands and scrolls to the active relation tab in its owning live connection, including views and column tabs. Objects absent from loaded metadata cannot be revealed.

- Relations are grouped into Tables, Views, Materialized Views and Other Relations using the provider's loaded metadata. Unknown relation kinds stay visible; each folder expands independently and opens the existing data/metadata workflow. Empty folders describe loaded metadata only. Providers that do not discover an object kind cannot populate that folder yet. Manual acceptance is deferred.
- DBeaver-style tree: connection → databases → schemas → tables → columns, constraints, foreign keys, indexes.
- Schema metadata (tables, columns, primary keys, constraints, indexes) is loaded in bulk when you connect.
- Right-click the connection, Databases, a database, Schemas, a schema such as `public`, Tables, or a table and choose **Refresh** to reload the owning connection’s metadata. The database menu opens **SQL Editor**, and writable schemas offer the existing **Create Table…** and **Create View…** dialogs.
- On writable PostgreSQL connections, **Delete…** on a visible schema or database opens a confirmation dialog and a SQL preview. Schema deletion starts in RESTRICT mode. Click the **CASCADE** checkbox or its row to include contained objects and any dependencies PostgreSQL resolves, including dependencies outside the schema. Empty schemas without a navigator row can be managed from SQL Editor. For database deletion, type the exact database name. FastDB opens a maintenance connection and then disconnects the target profile, which stays saved. Other active sessions may block the operation. If PostgreSQL refuses the deletion after FastDB disconnects, reconnect the retained profile to continue using the database.

## Table tabs
- The tab strip scrolls horizontally with a mouse wheel or trackpad and brings newly opened or selected tabs into view.
- Reopening a table in the same connection and schema selects its existing tab and preserves its results and staged edits.
- **Data**:
  - Results **stream into the grid**: the grid appears as soon as the columns are known and grows as row batches arrive.
  - **Search table data…** in the PostgreSQL table footer searches committed values visible to the connection role in the selected local heap table. Search uses a literal substring and the database collation. Supported scalar columns include text, numbers, booleans, UUIDs and dates/times. SQL NULL, binary and unsupported types are excluded. The dialog shows up to 50 matching rows with one matching column and a snippet per row. Cancel stops the dedicated read-only request. Select a match to reopen a read-only preview of that row version, even on a table without a primary key. Updates, table rewrites and rows that are no longer visible require a new search. The preview includes the matching column and up to 32 supported columns, with at most 512 characters per value. Table-level SELECT is required. The table footer searches one ordinary table or leaf partition.
  - On SQLite, **Search table data…** searches the open ordinary table in `main`. It matches text, integer and real values using ASCII case folding. SQL NULL, BLOB and text containing NUL are excluded from matching. Select a result to see the row as it appeared during the search, including rows from tables without a primary key or rowid. Previews show up to 32 columns and 512 characters per value. The same result limit and Cancel control apply.
  - On MySQL, **Search table data…** searches the open base table in its database. It matches supported scalar and JSON values using a case-folded UTF-8 literal substring. SQL NULL and binary columns are excluded from matching. Select a result for a captured preview of up to 32 columns and 512 characters per value. The same result limit and Cancel control apply.
  - **Find in result…** searches loaded values with literal, case-sensitive matching, including staged edits/new rows and displayed rows marked for deletion. Next/Enter and Previous/Shift+Enter scan cells in row order and wrap; empty input does not match, and SQL NULL/unset defaults are not text. Search text is limited to 4,096 UTF-8 bytes. Work runs in one cancellable background worker per workspace without collecting a match list or issuing SQL. A match selects and reveals its cell; opening Find pauses automatic fetch through dialog closure; later manual vertical scrolling or a new result restores it. Cancel search keeps the dialog open; Close cancels pending work; Escape first clears input selection, then closes. Replaced results, changed edits and newly opened cell editors reject stale matches. Search is unavailable without a loaded result. Desktop acceptance remains pending.
  - While a query runs, the execute button becomes **Cancel**. Cancellation uses the PostgreSQL cancel token, `KILL QUERY` on MySQL, and `sqlite3_interrupt` on SQLite.
  - Filter bar for `WHERE` / `ORDER BY` / `GROUP BY` fragments, a row limit (default 200), and a grid or plain-text view.
  - **Column menu**: move visible columns left or right, hide them, or restore all columns to source order. Copy, Find, edit navigation, and paste follow the visible layout. Changing the layout clears the selection and preserves staged edits.
  - **Multi-column sorting**: in table results, Sort ascending or descending replaces the current keys. Add ascending or descending sort key appends a lower-priority key or updates its direction. Criteria can filter multiple columns. Known primary key columns break ties during paging. Finish staged edits before changing server sorting.
  - **Paste**: Cmd/Ctrl+V stages a rectangular plain TSV block starting at the focused cell. It validates the entire block before staging a single Undo step. It accepts up to 1,024 cells and 256 KiB, fits within loaded rows and visible columns, and checks supported types from result metadata. The database still validates its constraints on Save. Empty text and the literal word NULL remain text. Right-click **Set SQL NULL** to stage NULL or **Use database default** to omit a field from a new row's INSERT.
  - **Related rows**: right-click a key cell to open referenced or referencing rows in a separate filtered tab. Composite keys use every component. A NULL or unset component cannot identify a referenced row. MySQL/MariaDB current-value navigation is limited to text keys. For an outgoing FK, **Choose key** opens a read-only table tab. Select a saved row and click **Use selected key** to stage every component together.
  - **Record** is an independent single-row toggle for both table and SQL results. Keep **Grid** selected for a two-column Name / Row #n table, or select **Text** for the same record as an aligned monospace text table. Switching Grid/Text keeps Record and its current row active. In a table data grid, select a cell and press **Tab** to see all its fields in a scrollable Name / Row #n view. Press **Tab** again to return to the selected cell. **Esc** cancels an in-progress cell edit and keeps the preview open. Select a value and open **Panels** to inspect it in the Value panel. Double-click a value to edit it inline using the same rules as the grid. Enter stages the edit for Save, and Tab advances to the next column. The Record button opens at the selected row, or the first loaded row; with no loaded rows it does nothing. Previous/Next navigate loaded rows without fetching more. Fields are paged 64 at a time with bounded value previews; staged edits, deletion markers, SQL NULL, empty strings and unset defaults remain distinct. **Copy record** and Cmd/Ctrl+C copy the displayed field page as formatted text. Refresh after staged edits. Toggle Record off, choose **All rows**, or press Escape to restore the complete result in the current Grid/Text presentation and select the inspected row when its snapshot is current. Result replacement/switching clears Record; Find returns to ordinary Grid. The Record button opens the read-only view.
  - **Criteria filters and history**: Criteria opens a searchable column picker with multiple AND/OR conditions, comparison/LIKE/NULL operators, literal values and optional ordering. Apply replaces the filter text and executes once; Cancel leaves it unchanged. Text values are quoted/encoded by provider (PostgreSQL E literals; MySQL/MariaDB UTF-8 hex conversion independent of backslash mode). Per-tab back/forward restores executed filter/order/fetch-size states, including structured criteria; new execution replaces the forward branch. History retains up to 100 states within an approximate 1 MiB budget plus the current state. Save/Cancel staged row edits before changing filters or history. Expand hides navigator/value panes while preserving their widths; Restore/Escape returns them. SQL preview is cached, bounded on screen and copyable in full; long input rendering preserves full Unicode values and selection.

  - Virtualized rows, auto-fit column widths, drag-to-resize, and double-click to auto-fit. Row and column lines continue through the empty part of the grid. The vertical scrollbar follows the actual grid bounds and reaches the bottom with the last row.
  - Right-click anywhere in the grid to open its context menu. Right-clicking empty space keeps the current selection. In table Data tabs, **Refresh** appears last and reloads the table using the same filters and staged-edit safeguards as ↻.
  - Cell/range selection by dragging the left mouse button across cells or using Shift-click, with `Cmd/Ctrl + C` for TSV. Releasing the mouse keeps the selected rectangle; double-click still edits a cell. Right-click a data cell for **Copy (TSV)**, **Copy as CSV** or **Copy as SQL INSERT**, in both table and script results. Right-click inside a selected rectangle to keep it; outside selects the clicked cell. Copies use displayed values, including staged edits and inserted rows. CSV has no header and writes NULL as an empty field; SQL includes only selected columns, uses provider-specific identifier/literal quoting and emits one INSERT per selected row. Table targets retain schema/name; script results use `query_result` (rename before executing). As with export, SQL uses text representations rather than a schema/binary backup. Menu copies run in the background with footer status and a 16 MiB output limit; failures leave the clipboard unchanged. Larger selections can use file export after saving/cancelling staged edits.
  - Inline cell edits, row insertion, duplication and deletion, with Save / Cancel and undo / redo. Table tabs own dedicated physical sessions on supported drivers:
    - In **Auto-Commit** mode, Save generates SQL and atomically executes and commits all changes.
    - In **Manual** mode, Save sends staged changes to the database without committing, reloading the table within the same session so uncommitted writes are visible (read-your-writes).
    - **Commit** applies any pending cell/row edits and commits the open tab transaction.
    - **Rollback** discards staged cell/row edits, rolls back any writes previously sent by Save, and reloads the table from the database.
    - Failed batches roll back to their savepoint without affecting earlier uncommitted writes.
    - Disconnecting or closing the tab closes the dedicated session and rolls back uncommitted writes.
  - **Export CSV / Export SQL** in the result footer saves all currently loaded rows from table or script results through a native save dialog. Fetch more rows before exporting if needed. Save or cancel staged edits first. Export runs in the background with status/errors in the footer; an existing destination is replaced only after the complete file is ready. CSV includes column headers, with NULL written as an empty field. SQL writes one INSERT per row with provider-specific quoting, using the table's schema/name or `query_result` for script results (rename that target before importing). Values use the result's text representation; this is a data export, not a schema or binary-type backup.
  - **Export HTML / Export Markdown** save the loaded result as a UTF-8 table with escaped headers and values. SQL NULL appears as italic NULL, empty strings as blank cells, and values from binary columns or invalid UTF-8 as hex. Markdown uses pipe tables and HTML line breaks; enable table support in the Markdown renderer.
  - **Export JSON** writes the loaded rows as a UTF-8 array of objects keyed by column name. Alias duplicate names before exporting. SQL NULL is JSON `null`, booleans are JSON booleans, and valid numeric tokens retain their exact digits. Non-finite numbers, JSON column source, dates and other text are strings. Values from columns reported as binary and invalid UTF-8 are written as hex strings.
  - **Full-source Export (All CSV / All SQL)**: **Export All (CSV)** and **Export All (SQL)** in the result toolbar stream all matching rows directly from the source table (respecting filter criteria without pagination limits) or the active result's `SELECT`/`WITH` statement, writing to an atomic temporary file before replacing the destination file upon successful completion. While it runs, the toolbar shows the rows written and **Cancel export**; cancelling keeps any previous destination file and deletes the temporary file.
  - **CSV Data Import**: **Import CSV…** in the table toolbar and **Import CSV Data…** in the navigator table context menu open the CSV import modal. Options: delimiter (comma, semicolon, tab, pipe), header row, encoding (UTF-8, UTF-16 LE, UTF-16 BE) and a NULL token (default `\N`; empty means no NULL token; only unquoted fields match, so a quoted `"\N"` stays text). The preview shows up to 6 sample rows, with NULL as `[NULL]`. Each destination column maps to a CSV column or *(skip)* (skipped columns use their native default) and a conversion (Auto, Text, Integer, Decimal, Float, Boolean, Date, Time, Timestamp, Timestamp TZ, JSON, UUID, Binary (hex)). Mapping starts by matching names case-insensitively; files without a header row need manual mapping. Commit policy is one atomic transaction (rollback on any error or cancel) or commit per batch (earlier batches stay committed); **Skip invalid values** rejects rows whose values fail conversion instead of stopping. Progress shows processed/committed/rejected rows; Cancel stops the run, and Escape or ✕ cancels it and closes the modal.
  - **Transfer to table**: **Transfer to Table…** in the navigator table context menu and **Transfer…** in the result toolbar stream rows into an existing table on any connected, writable connection. Table sources read all rows (the table tab's filter applies; the navigator entry has no filter); SQL results re-run the active result's statement on the connection; it must be a single `SELECT`/`WITH` statement without write keywords (`INSERT`, `UPDATE`, `DELETE`, `MERGE`, `INTO`, DDL, `CALL`; `FOR UPDATE` is also refused) outside quotes and comments. Full export uses the same rule. The source runs on the connection rather than the tab's transaction session. Filter destinations by connection, schema or table name (first 100 matches). Mapping, commit policy, invalid-value handling, progress and cancellation work as for CSV import. Transferring a table into itself is rejected.
- **Properties**: a scrollable detail pane with visible horizontal/vertical scrollbars for every section; stable column widths and expanding detail rows keep metadata readable. The Columns list uses single-line clipped cells with explicit line height to prevent long native type names wrapping into adjacent rows. Columns (type, nullability, default, collation, PK), constraints, indexes, and a DDL pane with a fixed **Copy DDL** toolbar. In DDL, `Cmd/Ctrl + A` highlights all SQL and `Cmd/Ctrl + C` copies it without line numbers; Escape or clicking the SQL clears selection. PostgreSQL generates executable structural DDL for ordinary/partitioned tables, views and materialized views: native column types/collations/defaults, identity/generated columns, owned serial sequences, constraints, indexes, comments, storage options, ownership, explicit grants, RLS/policies, triggers, rules and extended statistics. Partition DDL attaches to an existing parent. Materialized views replay WITH NO DATA and require an explicit refresh; native column types/domain nullability, indexes and storage settings are preserved. Referenced schemas, roles, types, functions and tables must already exist; data and current sequence values are excluded. Typed tables retain their OF dependency. Inherited source reports why DDL is unavailable when conflicting parent defaults or changed column order prevent faithful replay; foreign table DDL preserves the server dependency and native table/column options. Temporary table DDL is unavailable and invalid indexes are identified and omitted. MySQL and SQLite load native DDL for the selected relation. SQLite includes the relation’s explicit indexes and triggers. The DDL pane reports load errors and refresh retries the source read. PostgreSQL also shows native type precision/length, column comments, owner, OID, effective tablespace, table comment, RLS flags, persistence, partition key, estimated rows, table/index/total bytes and vacuum/analyze timestamps. Index methods, ordered expressions/INCLUDE columns, uniqueness, validity, predicates and full constraint/foreign-key definitions come from PostgreSQL catalogs. Metadata refreshes with the connection's schema refresh; unsupported or unknown values remain unavailable.
- **MySQL column metadata**: Columns preserves native type length/precision/unsigned attributes, default values, collation and comments. Generated columns remain inspectable and are excluded from automatic import/transfer mappings. The native DDL source distinguishes absent and explicit NULL defaults where the column catalog cannot.
- **SQLite column metadata**: Columns includes generated values, declared native types/default SQL and FK flags. Missing defaults, SQL NULL, literal text NULL and empty text remain distinct. PK nullability follows SQLite rowid-alias, ordinary nullable, STRICT/WITHOUT ROWID and inline PRIMARY KEY DESC semantics. Hidden virtual-table implementation columns are excluded; collation and other attributes without a native reader remain unavailable. Index summaries include native implicit UNIQUE and WITHOUT ROWID primary-key indexes; rowid aliases do not create a separate index entry. Generated columns are excluded from import and transfer destinations. An explicit NULL on a rowid alias still requests a generated key. GUI acceptance remains pending.
- **Metadata capability states**: drivers declare their implemented readers separately from live permissions and row counts. Properties distinguishes not loaded/disconnected, not implemented, provider unsupported, permission denied, failed and successfully loaded empty metadata. Optional metadata failures retain their message while table discovery remains usable; refresh retries the owning connection. Native PostgreSQL/MySQL permission codes are classified without matching translated text. The Virtual category is disabled with an explanation. SQLite/MySQL foreign-key rows use real source/target mappings even where native constraint definitions are unavailable; no actions/deferrability are inferred. GUI acceptance remains pending.
- **Full column values**: select a row in Properties → Columns to inspect and copy its full native type, nullability, collation, default and comment. Native spelling and multiline values are preserved; missing metadata is labelled unavailable/not reported. Double-click or Enter opens the column editor. Manual clipboard/layout acceptance is pending; see the [provider workflow checklist](../WORKFLOW_ACCEPTANCE.md).
- Columns summary now labels unreported collation/identity explicitly and shows a loaded-empty message rather than an empty grid. Missing collation does not imply the database default.
- **PostgreSQL catalog sections**: Properties loads Dependencies, References, Partitions, Triggers, Rules, Policies and Permissions asynchronously. Direct dependency/dependent rows retain relation navigation; parent/child partition links include bounds; triggers/rules expose native definitions; policies include roles, expressions and RLS flags. Permissions shows stored/default table and direct column ACLs, not effective privileges through role memberships or RLS. Copy source and relation navigation are available where applicable. Empty, failed, disconnected and provider-unsupported states are distinct, with retry and refresh. Catalog reads are read-only and independent of SQL-tab transactions; manual GUI acceptance is pending.

- **Diagram**: a selected-table ER view showing only that table and its direct incoming/outgoing FK neighbors with qualified table names and directed FK column links for PostgreSQL, MySQL/MariaDB and SQLite. The main table sits at the center, with neighbors balanced around all four sides and the initial viewport centered on it. Composite keys, self references and cross-schema targets retain their column mappings. Wheel/trackpad scrolling works on both axes with visible horizontal/vertical scrollbar tracks; middle-drag pans. Native macOS trackpad pinch, Cmd/Ctrl + trackpad/wheel, Cmd/Ctrl + plus/minus (0 resets), and the Zoom/Fit/Reset/Focus table controls navigate the layout, and double-clicking a table header opens its data tab on the owning connection. Card width fits the measured table title or widest column name, and clicking a column shows all available column metadata in the footer. Column rows show column names without data types or PK/FK text badges. Click a connector line to highlight the mapped FK and referenced columns at both ends (including all pairs of a composite constraint); arrowheads point to referenced columns. Each link has its own routing lanes and separate ports within the column row, including multiple links to the same key; connectors do not intentionally merge into shared trunks. The footer identifies the selected column link. Connection metadata and the focused layout are cached until schema refresh and only visible table cards are rendered; unsupported/failed FK metadata is shown explicitly. Drag anywhere on a table card, including column rows, to rearrange the diagram. Positions save on drop, restore when reopening the same table, and are removed when its connection is deleted. **Export SVG…** saves the whole focused diagram with its current card positions and FK routes. The standalone image uses a light palette, independent of viewport zoom and selection.

- **PostgreSQL column editor**: double-click a column in Properties/Navigator, or select it and press Enter, to open its own draft tab. Edit the name, native type (with catalog type suggestions and optional explicit USING expression), nullable flag, default SQL expression or multiline comment. Default removal is distinct from SQL NULL. Save/Cmd+S opens a quoted DDL preview; Persist applies one dedicated transaction and reads the catalog back, while Revert discards the local draft. Stable table OID/attribute identity and a locked snapshot check detect concurrent changes. Close, metadata refresh, disconnect, delete-connection and Quit guard dirty drafts with Save/Discard/Cancel. Connection/commit uncertainty requires Refresh before retrying. Owning connection caches refresh after success; old table grids retain staged edits but require reload before Save. Identity/generated columns, inheritance/partition tables, collation/storage/permissions editing and non-PostgreSQL mutations remain explicitly read-only/unsupported. Interactive GUI acceptance is pending the user's test.
