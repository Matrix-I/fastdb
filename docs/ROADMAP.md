Updated **2026-11-09** with workspace, navigator, result and transaction work through commit `7ddf580`. This is a source audit, not a live database or desktop acceptance report, and does not describe the older v0.1.0 release. Existing implementation plans describe intended work; they are not proof of completion.

Follow-up: [DBeaver GUI and business workflow analysis](DBEAVER_WORKFLOWS.md) specifies the column editor, draft/persist lifecycle and screen-family coverage. Direct DBeaver inspection is pending desktop permission; documentation-backed behavior is distinguished from proposed FastDB contracts.

## Status and completion rules

| Status | Meaning |
| :--- | :--- |
| Wired | A reachable UI action connects to implementation and presents an outcome in the stated scope. Runtime acceptance still needs evidence. |
| Partial | A useful subset is wired, but the wider workflow or provider coverage is incomplete. |
| UI only | A visible control or section has no action or real result for that feature. |
| Backend only / stub | Library types or code exist, but there is no usable application workflow. |
| Missing | No implementation of the described application workflow was found in the inspected code. |

A feature is complete only when the path **UI entry → action → driver/service → real result or persisted change → success/error/cancel feedback** works. For read-only viewers, require real source data and meaningful loading, empty, unsupported and failure states. A tab, icon, type definition, SQL preview or passing unit test alone does not close an end-to-end feature.

Completion must name supported providers and limits, add owning-crate tests, and record an app smoke test. Database changes need execution and read-back verification; destructive actions need SQL preview/confirmation and appropriate rollback/error behavior. Keep result processing bounded and heavy work off GPUI render. Use `cargo fmt --all`, `cargo clippy --workspace --all-targets`, and `cargo test --workspace`; live tests must distinguish skipped from passed. These are implementation gates, not claims that this documentation audit exercised every workflow.

## Existing workflows: preserve their actual scope

| Area | Status | Evidence and limits |
| :--- | :--- | :--- |
| Connection CRUD/test and credentials | Wired | `connection_dialog.rs`, `connections.rs`, `connection_config.rs`; native PG/MySQL/SQLite and vendor ODBC paths. Keychain save/migration errors have feedback. Provider availability is not equal to feature parity; see [provider validation](PROVIDERS.md). |
| TLS | Partial | PG/MySQL certificate/hostname verification and optional root CA are wired. Do not generalize to every ODBC/platform/authentication combination. |
| Navigator | Partial | `navigator/`, `nav_context_menu.rs`: tables/columns/constraints/indexes and connection actions in a separately resizable Connections panel. One search field filters Connections, Catalogs and schemas, Tables/procedures/etc. or saved Files from loaded metadata (capped at 100); the PostgreSQL catalog browser covers sequences, routines, triggers and types read-only. No object DDL action menu. |
| Table browsing | Wired | `query.rs`, `fetch_plan.rs`, `data_panel.rs`: streamed results, filter text, header ordering, fetch-next, cancellation and errors, with criteria builder and per-tab history (P0-03). Opening a table loads its data. |
| Grid edits | Partial | `data_edit.rs`, `db-wire/src/sql.rs`: table row edit/insert/duplicate/delete and transactional Save/Cancel. Table tabs own dedicated sessions: Auto-Commit Save commits atomically; Manual Save sends without committing (read-your-writes), Commit/Rollback end the tab transaction, failed batches roll back to a savepoint, close/disconnect rolls back. `can_edit_active_rows` requires a table target; arbitrary script results do not become editable merely because they use the same grid. |
| Clipboard/export | Wired, bounded scope | `grid_clipboard.rs`, `export.rs`: TSV/CSV/SQL copy and loaded-result CSV/SQL file export. Not a full-table transfer, import, schema backup or lossless binary backup; script SQL exports target `query_result`. |
| Value panel | Partial | `value_panel.rs`, `value_format.rs`: selected-cell formatted display, format picker, wrap and copy have actions. Not a structured value editor or BLOB file import/export workflow. |
| Properties metadata and DDL | Partial | `properties/`, `ddl.rs`, `db-wire/src/postgres/metadata.rs`: real PG columns/constraints/indexes/FKs/statistics and scoped structural DDL. Other providers have partial metadata/DDL; viewing/copying DDL does not create or alter objects. |
| SQL scripts | Wired, bounded scope | `sql_script.rs`, `script_store.rs`, `script_tools.rs`, `script_view.rs`: local autosave, chooser, rename/delete, execution, recent history and formatting. The result area stays hidden until the first execution and has a per-tab resizable editor/result split (15–85%). Sequential script parsing has documented dialect restrictions; retains latest 20 results. |
| SQL transactions/session state | Partial | `pinned_script.rs`, `db-wire/src/postgres/script.rs`: persistent tab sessions for PostgreSQL, MySQL/MariaDB, SQLite and supported ODBC (P1-05), Begin/Commit/Rollback and savepoints. Commit, Rollback and an Auto/Manual/isolation selector sit on the workspace toolbar. Session persistence means across runs in an open tab, not restoration after app restart. Smart commit is not implemented. |
| Transaction log | Wired | Session-only log of every executed SQL statement (scripts, table reads/writes, transaction controls, plans, CSV transfers, metadata) including failures/cancellations, via an additive db-wire execution observer. Stored in a private temp file deleted on exit and cleaned after crashes; the modal pages/searches from disk. Excludes bound values, credentials and result values. GUI acceptance pending. |
| Query plans | Partial | `query_plan.rs`, `db-wire/src/query_plan.rs`: PostgreSQL tree/raw JSON viewer, Explain and executing Analyze. Other provider plan adapters, comparison and richer profiling remain open. |
| Performance/packaging | Partial | Paged/spilling results, virtual grid, benchmark runner, macOS preview and updater exist. Original performance targets, broader platform distribution and signed/notarized release acceptance remain separate work. |

## Delivery order

Priorities below are proposed implementation order, not release dates. PostgreSQL is first for catalog and administration work; provider expansion follows capability tests. Every unchecked item is still open even if part of its UI exists. Checkboxes track implementation and automated validation; manual GUI acceptance is separately marked pending at the user’s request.

Current v0.2.0 acceptance scope (2026-11-05): PostgreSQL is required; MariaDB,
Oracle, SQL Server and Db2 desktop connections are disabled with **Feature is
coming**. MySQL and SQLite remain available but outside this manual gate. See
[the ordered PostgreSQL acceptance runbook](testing/0.2.0-postgres-manual-acceptance.md).
Source review for that runbook also found P1-08 GUI gaps (no transfer entry
point, no manual CSV mapping/encoding/NULL-token controls, no full-export Cancel
or live progress); these were implemented on 2026-11-09 and await desktop
acceptance.

### P0 — Make the existing UI truthful and finish its result paths

- [x] **P0-01 — Capability states (source audit complete; manual testing skipped by user).** Metadata availability, per-section failures, permission errors and loaded-empty states are distinct. Virtual is disabled with an explanation. Source audit found real actions on Expand/Criteria/history/diagram and no exposed SSH/theme no-op controls. Columns no longer invent default collation or blank identity metadata. Provider declarations have automated coverage; desktop/provider acceptance is not claimed.
- [x] **P0-02 — Missing Properties readers (implemented; GUI acceptance pending).** Implement Dependencies, References, Partitions, Triggers, Rules, Policies and Permissions for PostgreSQL. Acceptance: catalog fixtures with real objects produce navigable rows; empty/error states and refresh work. Keep mutation actions a separate milestone.
- [x] **P0-03 — Filter workflow (implemented; GUI acceptance pending).** Implement criteria builder and per-tab history; define expand behavior. Acceptance: generated predicate/order, executed SQL and returned rows agree; back/forward and refresh retain the intended state.
- [x] **P0-04 — ER relationships (implemented; GUI acceptance pending).** Replace the single entity preview with a usable FK diagram. Acceptance: composite/self-referencing/incoming/outgoing FKs render correctly and open the right connection/schema/table; layout and viewport remain responsive.
- [ ] **P0-05 — Workflow acceptance matrix (data paths automated for SQLite, PostgreSQL and MySQL; desktop execution pending).** [Provider matrix and repeatable protocol](WORKFLOW_ACCEPTANCE.md) cover connect → browse → run → edit/save/read-back → export/read-back → cancel/disconnect for each claimed provider, multi-connection identity, stale async completion, pending edits and failed transaction recovery. Manual execution is deferred to the user; no pending or skipped test is validated support. Since 2026-11-09 `workflow_test` also runs the full data path live against PostgreSQL 15.19 and MySQL 8.4.13 (connect, browse, script failure, edit/save/rollback/read-back, export replay, connection identity, cancel and disconnect rollback). MariaDB, ODBC providers and the desktop matrix remain open.

- [x] **P0-06 — Columns metadata layout and interaction (implemented; manual testing skipped by user).** Single-line clipped rows, full native metadata inspection/copy and double-click/Enter object navigation are wired. Missing collation/identity are labelled not reported; loaded-empty Columns has explicit feedback. Narrow/HiDPI and desktop clipboard behavior remain unverified.
- [x] **P0-07 — Column object editor and schema drafts (implemented; GUI acceptance pending).** Open a dedicated column tab with actual native attributes; edit name/type/nullability/default/comment with capability gating, Save SQL preview, Persist, Revert and catalog read-back. Include dirty-close handling, conflicts and failure recovery. See the [field and lifecycle contract](DBEAVER_WORKFLOWS.md). Keep identity/generated/storage/permissions transitions separately capability-tested.
- [x] **P0-08 — Reliable application Quit (implemented; manual testing skipped by user).** Global menu dispatch defers window access; keyboard/menu/window-close enter the save-before-quit path, with dirty-column guards, script saves, queue flush and dirty recheck. Save-queue failure/retry has automated coverage. Focus-context desktop dispatch remains unverified.

### P1 — Daily database development workflows

- [x] **P1-01 — Object explorer and search (implemented; desktop acceptance pending).** PostgreSQL extended object browsing and on-demand metadata/source plus connection-qualified persisted favorites are wired.  The active connection supports literal substring search over loaded relation/schema and column names, with qualified navigation. Reveal active object expands the owning live connection and native relation folder, selecting the qualified relation and scrolling it into view. Since 2026-11-06 a single navigator search field with a filter-mode menu (Connections, Catalogs and schemas, Tables/procedures/etc., Files) replaces the separate Search/Browse controls. Dedicated views/materialized views, sequences, functions/procedures, triggers, types and database/schema nodes with capability-aware loading; object search/filter, refresh, reveal active object, folders/favorites. Acceptance: selection resolves to the correct object and opens real metadata/source.
- [x] **P1-02 — Schema/object editing (implemented; desktop acceptance pending).** Create/alter/rename/drop tables, columns, constraints, indexes and views; truncate table with confirmation. Modal provides interactive form fields, column management for create table, live dialect-aware SQL preview, validation, execution on isolated connection with 15s deadline, transactional rollback indicator (PG/SQLite) vs non-transactional implicit commit warning (MySQL/MariaDB), destructive danger alerts, copy SQL, and automatic navigator catalog refresh on success. Acceptance: automated SQL generation, isolated execution, catalog mutation, and truncation verified with unit and integration tests; manual GUI acceptance remains deferred.
- [x] **P1-03 — SQL editing essentials (implemented; desktop acceptance pending).** Comment/uncomment and four-space indent/outdent toolbar actions operate on selected lines/current line with Undo and autosave. Find/Replace supports case-sensitive literal matching, wrapped navigation, selected-match replacement and one-step Replace All. External UTF-8 `.sql` files import as independent autosaved scripts; Save SQL copy writes a snapshot to another destination. Richer dialect keywords (PostgreSQL/MySQL/SQLite/ANSI) and parameter tokens (`:param`, `@param`, `$1`, `?`) highlighted. Real-time syntax diagnostics flag unterminated strings, comments, and syntax parse errors. Standard searchable SQL snippets and templates (Query, DML, DDL, Advanced) insert at cursor with full Undo support. Interactive parameter binding modal prompts for typed values with live SQL preview and tab-session persistence before execution. Acceptance: actions modify/execute the intended selection and remain undoable; parameters are typed safely.
- [x] **P1-04 — Execution feedback and controls (implemented; desktop acceptance pending).** SQL tabs retain the latest 100 execution outcomes while open (no restart persistence, per user choice), with timing, result/command count distinction, bounded PostgreSQL notices, MySQL warning details and native PostgreSQL error positions. Per-tab timeout presets default off; workspace-wide single-operation policy reports busy refusals and retains ownership through cancellation cleanup. ODBC informational diagnostics/structured positions remain unsupported. Acceptance: distinguish result rows from DML counts, expose errors without losing earlier statement outcomes.
- [x] **P1-05 — Transaction/provider parity (implemented; live ODBC/MariaDB and desktop acceptance pending).** Pinned sessions for MySQL/MariaDB, SQLite and supported ODBC providers; autocommit/isolation controls, active database/schema selection, savepoints and transaction-state visibility. Add vendor batch/procedural syntax with dialect tests. Acceptance: session variables/temp tables survive across runs; commit/rollback and failure recovery use that same session. SQLite/MySQL tab sessions, native transaction feedback, isolation selection and native MySQL/MariaDB plus client-managed PostgreSQL/SQLite autocommit controls are wired; Database/schema selectors, ODBC tab sessions and vendor batch preflight are wired. Table tabs now own dedicated sessions with Auto-Commit/Manual Save, Commit/Rollback and batch savepoint recovery; workspace toolbar transaction controls and a session-only Transaction log are wired (2026-11-06/07). Live ODBC, separate MariaDB and desktop acceptance remain open.
- [x] **P1-06 — Grid productivity (implemented; desktop acceptance pending).** Multi-column sorting/filtering, hide/reorder columns, result find, record view, FK value lookup and related-row navigation. Add validated multi-cell paste, explicit NULL/default handling and editable query results only when origin/key mapping is unambiguous. Acceptance: operations affect the intended rows and preserve staged edits safely. Partial implementation: loaded-result Find, Record, multi-column sorting and criteria, column visibility/order, validated TSV paste, explicit NULL/default actions, and FK value lookup with related-row navigation in either direction are wired. FK candidate selection can stage a selected target key. PostgreSQL Load editable result supports verified direct schema-qualified SELECT * results with complete primary keys and scalar non-key updates, guarded writes and read-back. Broader query/provider editing remains capability-gated. Record is a read-only single-row toggle combined with Grid or Text presentation, and table/SQL results share an aligned plain-text table (2,000 rows, 255 characters per column). Desktop acceptance is assigned to the user.
- [x] **P1-07 — Value editing (implemented; desktop acceptance pending).** Bounded text/JSON/XML source and binary hex editors, background value viewer and file load/save, strict UTF-8/UTF-16 encoding and timezone-aware UTC display. Apply stages one undoable change and rejects stale results/connections/edits; table Save preserves binary and NULL/empty/default distinctions. JSON formatting preserves original numeric tokens and duplicate keys; XML source stays unchanged. SQLite, PostgreSQL and MySQL have real write/read-back coverage. The 256 KiB limit is explicit; larger LOB streaming and schema-aware XML validation remain follow-ups. ODBC live checks stay deferred to Linux; Oracle empty binary edits are explicitly unavailable. Desktop acceptance is assigned to the user.
- [x] **P1-08 — Data import and transfer (implemented; desktop acceptance pending).** CSV import with delimiter/encoding/header/NULL/type mapping, sample preview grid, batching and error policy (atomic rollback vs per-batch durability); table/query-to-table streaming transfer with backpressure, and full-source streaming export to CSV and SQL INSERTs with atomic file replacement. Interactive modal wizard with live progress reporting and cancellation. Acceptance: read-back values/counts, cancellation, explicit partial-commit behavior, constraints and rollbacks covered across SQLite, PostgreSQL, and MySQL test suites; manual GUI acceptance remains deferred. Desktop UI (2026-11-09): navigator and result-toolbar Transfer entries with a filtered destination picker, per-column source/conversion mapping, CSV encoding and NULL-token controls, and full-export Cancel with live row count.
- [x] **P1-09 — Connection usability/security (implemented; desktop acceptance pending).** PostgreSQL, MySQL and MariaDB support fingerprint-pinned SSH, password or private-key jump authentication, and PKCS#12 client identity with server hostname verification. Saved profiles support timeouts, PostgreSQL application names, navigator groups/colors and OS-keychain secrets. PostgreSQL, MySQL/MariaDB and SQLite apply read-only safeguards in the driver and workspace. Automated coverage includes PostgreSQL, MySQL, SQLite, TLS over SSH and macOS certificate-only rejection. Separate MariaDB and vendor ODBC live checks remain deferred where the containers are unavailable.
- [x] **P1-10 — Workspace preferences (implemented; desktop acceptance pending).** Restore open tabs/layout and unsaved editor state after restart without executing SQL or resurrecting live transactions; configurable shortcuts/fonts/theme (Light/Dark toggle via View menu and `Cmd+Shift+T`, editor zoom `Cmd+=`/`Cmd+-`/`Cmd+0`, sidebar toggle `Cmd+B`) and persisted panel/grid preferences via atomic versioned JSON. Acceptance: reopen the right scripts/connections; never replay SQL or pretend to restore a live transaction.

### P2 — Administration, analysis and broader parity

- [ ] **P2-01 — Database object administration.** Routine source/edit/run with arguments, sequence inspection/reset, trigger/rule/policy editing, partition management, roles/users and grant/revoke UI. Acceptance: preview, provider execution, refreshed catalog and permission-error feedback.
- [ ] **P2-02 — Backup/restore and maintenance.** Native-tool backup/restore, vacuum/analyze/reindex and provider equivalents. Acceptance: executable discovery/options, progress/logs/cancel and a verified restore into an isolated database.
- [ ] **P2-03 — Session/lock monitoring.** Active queries, sessions, blocking chains and terminate/cancel actions with confirmation. Acceptance: live refresh and verification that the selected server session was targeted.
- [x] **P2-04 — Data/schema search.** Definition search is implemented in the PostgreSQL, MySQL and SQLite drivers. Live definition and table data search checks passed on all three providers. Desktop acceptance preceded the removal of definition and multi-table data search from the Connections panel. The open table footer supports single-table data search with bounded results, cancellation and row previews (PostgreSQL row-version previews and MySQL and SQLite captured previews).
- [x] **P2-05 — Plan and statistics coverage (implemented for PostgreSQL, MySQL and SQLite; GUI acceptance pending).** PostgreSQL/MySQL/SQLite estimated plans, PostgreSQL/MySQL/MariaDB actual-plan adapters, typed estimates versus observations, expensive-node navigation and Save/Open JSON comparison are implemented. MySQL 8.4.13, MariaDB 11.4.13 and PostgreSQL 16.15 native-plan session tests passed; SQLite has real in-process session coverage. SQLite column metadata now includes generated columns, native types/defaults, FK flags and effective PK nullability. SQLite Properties includes native index details, primary/unique/foreign-key summaries with ordered key columns, native FK actions and stored row estimates. MySQL column readers preserve native types/defaults/collation/comments and generated identity. MySQL base-table statistics show stored row estimates, data/index sizes and table comments. MySQL index details show ordered keys, native methods and optimizer visibility. Constraint details show ordered columns, CHECK source/enforcement and native FK actions. PostgreSQL materialized views now reach discovery/Properties with native columns/details and replayable structural DDL (WITH NO DATA). PostgreSQL typed and inherited source supports native replay where possible and reports unavailable source for conflicting parent defaults or unreproducible column order. PostgreSQL foreign table source preserves native options, its server dependency and partition attachment. PostgreSQL temporary relations visible to the metadata connection emit structural `TEMPORARY` source using `pg_temp`, with an explicit `ON COMMIT` unknown/PRESERVE ROWS warning for temporary tables and cross-session replay coverage. SQLite/MySQL scoped relation DDL and a SQL Server estimated-plan adapter are implemented. P2-05 completion is scoped to PostgreSQL, MySQL and SQLite. MySQL table/view and SQLite ordinary/view/WITHOUT ROWID DDL replay have automated coverage. The Properties/DDL reference layout has cached SQL token colors and a line-number gutter. Vendor ODBC adapters are excluded from this milestone. MariaDB/ODBC desktop availability is unchanged; manual GUI acceptance remains pending. See the [completion checklist](plans/2026-11-12-p2-05-completion.md).
- [ ] **P2-06 — Comparison.** Start with read-only object/schema and keyed data diffs; then reviewed synchronization SQL, dependency ordering and execution/read-back. Handle large datasets and cross-provider type differences explicitly.
- [ ] **P2-07 — Transfer formats and analysis.** JSON and spreadsheet import/export, HTML/Markdown output, configurable formats, result aggregates/charts and ER image export. Validate type/NULL handling and output contents for each format. HTML, Markdown and JSON output is wired for loaded results, and focused ER diagrams export to SVG. Desktop acceptance is pending.
- [ ] **P2-08 — Reusable tasks.** Saved import/export/script/maintenance configurations, task history and optional scheduling with credential references, cancellation and useful failure reports.
- [ ] **P2-09 — Provider/platform validation.** Live Db2 validation, broader ODBC TLS/OS tests, native Windows support if adopted, repeatable Linux artifacts and macOS signing/notarization. Do not equate a provider preset or successful compile with a supported release workflow.
- [ ] **P2-10 — Performance acceptance.** Cold-cache startup, live-provider latency, large metadata trees, mixed-width/LOB results and memory/scroll regressions. Publish reproducible measurements separately from aspirational targets.

### P3 — Optional extensions, not prerequisites for core parity

- [ ] Cloud/NoSQL/analytical providers, IAM/SSO and proxy integrations based on demand; preserve native driver architecture.
- [ ] Remote storage, team/shared workspace configuration and collaborative workflows.

## Comparison baseline and references

The baseline is common desktop database work, primarily DBeaver Community workflows. Commercial capabilities are optional comparison targets, not claims that every DBeaver edition includes them. In particular, DBeaver's detailed Schema Compare is documented for Enterprise/Ultimate; simple object comparison and full migration must not be conflated. Check edition/provider support when starting each item.
