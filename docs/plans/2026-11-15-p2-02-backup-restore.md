# P2-02 Backup, Restore and Maintenance Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: development-superpowers:subagent-driven-development or executing-plans-strict. Steps use `- [ ]`.

**Goal / Architecture / Tech Stack / Branch:** Deliver the FastDB navigator workflow for P2-02. Use Rust and GPUI with independently supervised native client processes. Implementation branch: `feature/p2-02-backup-restore`. Base: `f1945ab`.

## Confirmed Requirements

- PostgreSQL, MySQL and SQLite are in scope.
- Restore is available only for a new or empty target. Acceptance uses a database isolated from the backup source.
- Backup supports an entire database and object selection where the native client supports it.
- Provide executable discovery, provider options, progress, logs, and cancellation. Cover PostgreSQL VACUUM, ANALYZE, REINDEX and native equivalents where available.

## Global Constraints

- Preserve profile transport, read-only semantics and credential confidentiality. Suppress write operations when the target configuration cannot be honored.
- Keep native process supervision, filesystem work and database operations off the GPUI render path. Stream artifacts and bound retained diagnostics.
- Never pass passwords in command arguments, invoke a shell, interpolate unchecked SQL identifiers, or overwrite an existing backup artifact.
- Report canceled, failed and completed runs based on process exit and artifact publication. Reap children and explicitly report the possibility of partial MySQL restore on failure.
- Commit only with explicit authorization. Run `cargo fmt --all`, `cargo build`, `cargo clippy --workspace --all-targets`, and `cargo test --workspace`. Launch the app and leave desktop acceptance to the user. Run independent review after verification.

## Technical Defaults

- PostgreSQL custom archives use `pg_dump` and `pg_restore`; transactional restore avoids a partially applied archive on command failure. Use `vacuumdb` and `reindexdb` for maintenance.
- MySQL uses `mysqldump` and the `mysql` client, with provider-native table analysis and optimization. MySQL SQL dumps require a trusted source and target credentials limited to the restore database.
- SQLite uses the native shell's online backup facility; use file-level backups for whole databases and native SQL for VACUUM, ANALYZE and REINDEX.
- Use GPUI's existing file pickers and a navigator action. Source reviewed for these entry points includes `crates/app/src/workspace/nav_context_menu.rs`, `connection_state.rs`, `drop_object_modal.rs` and `query_plan/file_actions.rs`.

## Risks & Rollback

- Target contents or identity can change after a UI selection. Validate against the actual target immediately before restore and refuse known nonempty targets. A stale navigator snapshot is insufficient.
- Client and server versions can disagree. Resolve the native executable explicitly and retain the process failure for diagnosis.
- Cancellation can leave MySQL DDL applied. Report the outcome and require a fresh or cleaned target before retrying.
- A failed or canceled backup can leave incomplete bytes. Stage output in the destination directory and publish only after successful completion.
- Reverting app code removes the feature. User-created artifacts and provider changes remain subject to the provider's backup and recovery procedures.

## Native feasibility evidence

- PostgreSQL 16 local temporary Unix-socket cluster: a custom-format dump restored into a separate database with `--single-transaction`. Ordered source and target values matched for NULL, empty text and binary bytes `00ff`. `vacuumdb`, `vacuumdb --analyze-only`, and `reindexdb` all exited successfully with verbose output.
- SQLite system client: `.backup` and `.restore` into a separate local file preserved NULL, embedded NUL, and binary bytes `00ff`. VACUUM, ANALYZE, REINDEX, and integrity check passed.
- MySQL 8.4.13 in a temporary Podman container with networking disabled: restored both a full dump (two tables) and a selected-table dump (one table) into separate databases. Ordered read-back matched NULL, empty text and binary bytes `00ff`. Native `ANALYZE TABLE` and `OPTIMIZE TABLE` returned `status OK`. The image does not provide `mysqlcheck`, so the probe used `mysql` for both operations.
- All three fixtures were cleaned up. These probes exercised native clients directly. App-level provider integration, restore isolation and desktop acceptance still require verification.

### Review fixes in progress

- The Unix wrapper regression held the descendant's stdin open after cancellation before the fix. The native runner now starts each client in its own process group, signals that group on cancellation or timeout and reaps the wrapper. The new test observed EOF after cancellation. The 16-test native suite passed with the SQLite CLI fixture enabled.
- PostgreSQL 16 SCRAM fixture with two populated partitions restored zero rows when the selected parent used `--table`. The same test restored both rows after switching to `--table-and-children`. Scoped backups now need a compatible `pg_dump`, and the provider guide covers selection of its directory.
- MySQL 8.4 isolated reproduction confirmed the restore routing bug. A native `mysqldump --databases source_db` captured a row with ID 1. After changing the source ID to 2, loading that dump with the adapter's `mysql --binary-mode --local-infile=0 --database=restore_db` flags set the source ID back to 1 and left the target with zero tables. The running container was removed after the probe.
- The old PostgreSQL check/restore split allowed two successful emptiness checks followed by two disjoint restores into one database. The PostgreSQL adapter now stages output from `pg_restore` privately and applies it with `psql --single-transaction` after acquiring an advisory transaction lock and checking the target in that same session. In a live PostgreSQL 16 fixture exactly one concurrent restore completed. A separate connected session also caused the expected refusal.
- MySQL now verifies complete `SHOW GRANTS` output for an exact schema-wide grant without broader privileges, and prefixes the target check and advisory lock in the same native client session as the import. The MySQL 8.4.13 fixture exercised whole and scoped restores under separate accounts, rejected a populated target and broader credentials, denied both `USE source_db` and a qualified source update while preserving source values, and admitted exactly one of two restores targeting the same empty schema.
- SQLite 3.54 CLI feasibility probe: `.dump fixture_x` matched unrelated `fixtureyx` because the object pattern interprets underscores as wildcards. It also emitted an empty string for a text value containing NUL. Scoped SQLite backup needs exact selection and binary preservation for the same data types as full-image backup.
- A SQLite native-image probe backed up to a private copy, dropped excluded objects, vacuumed, then backed up the compacted image. The result contained only the selected table and its index, preserved embedded NUL, BLOB bytes and a sequence value above the current maximum ID, and passed integrity check. A raw-byte search also confirmed the excluded fixture value was absent after compaction.
- SQLite now uses the native-image approach for scoped ordinary tables and views. An app-dispatch live test restored an exact table whose name contained wildcard and quote characters, omitted a similar sibling plus its index and view, and preserved input bytes, index and sequence. A stale out-of-scope sequence entry reproduced a privacy leak in the first implementation and is removed before compaction. The native suite passed 18 tests. `EXPLAIN QUERY PLAN` on a 1,001-table fixture showed one materialization of the table catalog and one scan to generate the drop plan. It generated 1,002 statements in 11 ms including client startup.
- PostgreSQL 16 native adapter live coverage passed with a private TLS CA and hostname verification. The fixture independently read `pg_stat_ssl.ssl = true` for the native connection before running backup, restore, concurrency and maintenance cases.
- Round-two review confirmed the original five findings were addressed.
